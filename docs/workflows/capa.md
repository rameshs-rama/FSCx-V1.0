# CAPA Workflow

## Objective

Manage corrective and preventive actions with evidence and effectiveness checks rather than marking issues "fixed" based only on implementation.

## Flow

Issue Identified
→ Containment
→ Root Cause
→ Corrective Action
→ Implementation
→ Effective Date / Effective Batch
→ Verification
→ Market/Internal Effectiveness Monitoring
→ Closure

## CAPA record

Capture:

- source
- linked ticket/NCR/batch
- problem statement
- severity
- containment
- root cause
- corrective action
- preventive action where relevant
- owner
- due date
- implementation date
- CAPA effective batch/date
- evidence
- verification method
- effectiveness result
- closure date
- approver

## Closure rule

CAPA must not close merely because an action was completed.

Effectiveness evidence is required.

## Complaint classification

Use manufacturing batch/date and CAPA effective batch/date.

### Legacy Market Exposure
Product manufactured before corrective action.

### Post-CAPA Watch
Post-fix product or suspected recurrence, cause not yet confirmed.

### Confirmed CAPA Recurrence
Post-fix product and same failure mode/root cause confirmed.

### New Failure Mode
Different cause.

### Installation / Usage
Not a manufacturing failure.

### Not Factory Related
Marketplace, wrong-product, fraud, fulfillment, or other non-factory cause when evidence supports it.

## Key KPI

Post-CAPA recurrence must be reported separately from total complaint volume.
